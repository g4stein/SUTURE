# PBT Discoveries

Real bugs caught by `fast-check` properties during the Suture build. One row per distinct counterexample. Rows are added by the `pbt-on-core-save` hook and the `pbt-adversary` agent. Only replayable counterexamples (with seed and path) are logged.

| Date | Commit | Property | Shrunk Counterexample | Root Cause & Fix |
|------|--------|----------|-----------------------|------------------|
| 2026-11-20 | d5c94a7 | `parse(print(ast)) ≡ ast` (packages/core/src/__tests__/parser.pbt.test.ts) | `AA(#N/A/FALSE)` — `{ seed: 20261120, path: "50:1:0:4:3:3" }`, shrunk 5 times from `call(AA, [binary('/', err #N/A, bool FALSE)])` | The lexer matched error literals with the greedy pattern `#[A-Za-z0-9/]+[!?]?`, so `#N/A/FALSE` became one unknown token and the printed formula failed to parse. Fix: match only the 12 known error literals, longest first (`#DIV/0!` … `#SPILL!`). Fixed in d5c94a7; the property now passes 2,000 runs. |
| 2026-11-20 | 3fb78ed | `fast-formula-parser` differential oracle agrees with Suture on numeric functions (packages/core/src/__tests__/functions.pbt.test.ts) | `MOD(1, -3)`: oracle `-2` (correct: `1 − (−3)·floor(1/−3) = −2`), Suture's formulajs-backed kernel `-1`. Generated tuple `[[0,…],1,-3,2]`, `{ seed: 6105, path: "4:0:0:0:0:0:0:0:0:2" }` | First seen as a failing row in the conformance table (`MOD(5,-3)` returned `-2` through formulajs); the differential property then reproduced it as a replayable counterexample. formulajs computes `MOD` as `±abs(n % d)` with the divisor's sign, which is wrong whenever `n % d ≠ 0` and the signs differ. Spreadsheet semantics are `n - d * FLOOR(n / d)`, so `MOD(5,-3) = -1` and `MOD(1,-3) = -2`. Fix: `MOD` became a native kernel per Spec 01 §6.4 (`#DIV/0!` on zero divisor). Fixed in 3fb78ed. Attribution: the conformance table found it, the property confirmed it. |

## Other defects found by the verification gate

These defects were not found as shrunk property counterexamples, so they do not belong in the table above. Each was found by a real-engine test or a measurement. Each row states how it was found and what now guards it.

| Date | Commit | Defect | How found | Repro | Root Cause & Fix |

| 2026-11-20 | cae91a1 | exceljs shared-formula translation rewrites quoted sheet names | Example test with a real exceljs-generated workbook (`packages/web/test/ingest.test.ts`, ".xlsx: real exceljs-generated workbook …") | Master `Notes!B4 = 'Q3 Plan'!B2*2` shared to `B5`. exceljs produced `'Q4 Plan'!B3*2`, a sheet that does not exist. The expected result is `'Q3 Plan'!B3*2`. | exceljs's translator shifts every letter+digit run, including text inside quoted sheet names. Fix: Suture's own `translateSharedFormula` (`packages/web/src/workers/ingestHandler.ts`) shifts only unanchored references and copies string literals and quoted sheet names verbatim. A follow-up property guards it: shifting forward then back is the identity, and quoted text and `$`-anchored parts never move (`ingest.test.ts`, "shared-formula translation (property)"). |
| 2026-11-20 | dc77fb6 | Exorcist float domains starved their upper range | Measurement. Flagship 2 fresh-seed discovery took 3.4–18.3 s over 8 seeds, and the first failing run came at index 17–737. Its flaw covers 7.4% of the domain under value-uniform sampling (`packages/web/test/flagships.test.ts`, estimation test, 1,000 samples). | The Exorcist hit rate was about 0.36% of runs, 20× below the region's share. At that rate about 3% of seeds would find nothing in 1,000 runs. | `fc.double({min, max})` is uniform over IEEE-754 bit patterns. On `[0, 0.35]` almost every draw lands near 0, but the flaw needs high promo and loyalty discounts. Fix: float domains map `fc.integer({min: 0, max: 0xFFFFFFFF})` linearly onto `[min, max]`. This keeps deterministic replay, gives exact `min` and `max` from the integer bound bias, and shrinks toward `min` (Spec 03 §4.1). Over 6 fresh seeds afterwards, the first failing run came at index 1–29. |
